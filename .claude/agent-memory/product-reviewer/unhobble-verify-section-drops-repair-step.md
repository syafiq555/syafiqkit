**On the 2026-08-18 pass over `skills/agent-setup/SKILL.md` + `references/agent-setup-verification.md`** (the "state what to establish rather than which command establishes it" rewrite), Step 1's old text ended with an explicit terminal action: "**Update whatever any check flags.**" The rewrite kept the judgment framing ("decide which side is right before changing either") but dropped the imperative that closed the loop — nothing in the new Step 5, the new reference file, or the Output section instructs writing a found gap back into the agent file via Step 4's mechanism. The old reference file's closing `## Interpretation` section ("If checks fail... Fix by re-reading CLAUDE.md and extracting...") was deleted outright with no replacement.

**Why this matters**: A future session running `/agent-setup` against stale agents reaches a real, well-reasoned verdict ("this agent lacks capability X the template has") and then the skill's own text stops — Step 5 is phrased entirely as diagnosis ("is a finding to judge," "which side is stale," "what counts as a missing capability"), never as "then write it." This is invocation-outcome breaking, not a wording defect: the skill's whole point is closing the gap between agent and template, and the text describing HOW to close it is gone even though the text describing how to DETECT it is excellent and much improved.

**How to apply**: When reviewing an unhobble pass on any Verify/Step-N-shaped section (grep checklist → judgment prose), don't just check that the *diagnosis* survived in better form — grep the pre-rewrite version for the sentence that told the reader what to DO with a positive finding ("update," "fix by," "regenerate," "write back") and confirm an equivalent imperative exists post-rewrite. A rewrite that makes the finding-quality much better while quietly turning the whole section into a read-only audit is the shape to flag as 🔴, not 🟡 — judgment prose is harder to audit for a dropped imperative than a bulleted checklist was, because prose reads as complete even when it only diagnoses. See [[unhobble-drops-standing-rule-pointer]] for the sibling failure mode (dropping the *citation* rather than the *repair instruction*) — both are instances of the same task-doc-named trap: "compression keeps the rule, drops the mechanism."
