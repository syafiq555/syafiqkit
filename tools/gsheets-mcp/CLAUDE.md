# gsheets-mcp: decisions and traps

Setup and the tool list are in `README.md`. This file records why it is built this way.

| Decision | Why |
|---|---|
| Our own server rather than `domdomegg/google-sheets-mcp` (05/11/2026) | That server takes one access token from an env var at start, so every call after an hour answers 401. Its `spreadsheet_get` output schema also strips `sheets[].data`, so colours, runs, chips and validation never come back. Sessions kept writing REST scripts around both |
| bun + `@modelcontextprotocol/sdk`, same shape as `tools/remote-cli` | One runtime for the plugin's tools. The launcher resolves bun from fixed paths because MCP servers start without the shell profile's PATH |
| Switched on per project at `--scope local`, never user scope or a repo `.mcp.json` | Only the projects that use Sheets load it. A shared repo's `.mcp.json` would hand teammates an entry pointing at a sign-in they don't have |
| One token with `spreadsheets` + `drive.file` + `drive.readonly` (the last added 10/11/2026, Syafiq's call), stored apart from `~/mcps/gsheets-config` | A Sheets write touching a Drive chip needs Drive read access to the linked file on the same token, and `drive.file` covers only the tool's own files. A refresh token minted before a scope change keeps refreshing with its old scopes, so the change takes effect only after `auth` runs again. The old spreadsheets-only and drive-only tokens stay for scripts that use them (beacon-mart's `publish-google.py`) |
| `cell_append_line` compares the colour shown at each position, not run lists | Google normalises runs on write: a run at index 0 becomes the cell's own text format, and a default-black run at 0 in an empty cell is dropped. Comparing run lists raised false alarms on live sheets (05/11/2026) |
| Run indices are JS string offsets | Google counts runs in UTF-16 units, which is what JS `length` gives. Checked live with an emoji before the appended line |
| `cell_replace_text` takes the exact text, not "my line" or a prefix (10/11/2026) | Any reply shape works (a multi-line list included), and a single-match rule means it can never hit someone else's line. After the replaced span it re-states the colour in force there, since Google applies a run until the next one |
| New text gets explicit link runs for its URLs (trailing `)`, `.`, `,` and unbalanced brackets left out), a replaced link is carried to its text when that text survives once in the replacement, and `cells_read_rich` shows each run's `link` (13/11/2026) | A reply's `(screenshot: …/view)` reached the client linked to `…/view%29`, Drive's error page, and the read showed only a blue run, not where it pointed. Re-linking by hand then needed a raw `updateCells` restating every run of a client's cell. The read-back check now names a link Google dropped, and skips a link at index 0, which Google may fold into the cell format. Checked live the same day on a scratch sheet: a bracketed URL, an edit around it, a cell starting with a URL. Links take the line's colour plus underline, not Google's link blue, so the colour-at-position checks still hold |
| After changing `src/`, reconnect `gsheets` in `/mcp` before testing through the tools | `bin/enable` registers it with `claude mcp add`, so `/reload-plugins` ("0 plugin MCP servers") leaves the old process serving the old tool list. Missed on 09/11 and again on 10/11, both times with the fact sitting in a reference nobody opened while editing here |
| A Drive chip cell is rewritten by collapsing each chip to `@` (`collapseChips`), never refused up front (10/11/2026) | On read, a chip spans its file's title; on write, Google accepts only one `@` per chip, with runs that each carry a chip ("Chip run must have a chip" if the read's end marker is sent back). It re-fetches the linked file on every rewrite and answers "Error fetching chip data: Permission denied" when the sign-in can't open it. Under `drive.file` that is every file the tool didn't create, so a client's attachment fails until the scope or the file's sharing changes. The write is all-or-nothing, so attempting is safe, and the error names the file |
| `cells_awaiting_reply` reads authorship from text colour, and lists only cells where another colour follows your last line (10/11/2026) | Checking a 64-row client tracker, `values_get` (60 KB) and `cells_read_rich` (118 KB) both spilled to files, so the session scripted over the dumps in Python; its first pass read each cell's last line by name prefix and missed client lines with no name and a question mid-cell. Colour is how both sides already mark who wrote what. A row we still owe without a new client line (our own stale promise) has no colour signal, so the tool description says to read those rows separately |
| `cells_awaiting_reply` takes `askColumn` (rows asked in another column with an empty reply cell, `newRow: true`) and `myNames` (a line in your colour signed "Other dd/mm:" counts as theirs, colour `signed:<name>`); both opt-in, so a call without them behaves as before (13/11/2026) | On a CRP45 tracker pass it listed nothing for two new rows whose question sat in column B with the reply cell empty, and nothing for a client's "verified in stg" typed in black. Neither has a colour signal, so the caller names the ask column and its own signers. Name matching stays opt-in because the colour rule exists to stop name-prefix reading from missing unsigned lines |
| `drive_file_share` posts one Drive permission and returns the file's permission list; a user share sends no email unless `notify` (14/11/2026) | `explainer-deck` told sessions no tool could share, so a deck uploaded here went to the user as Drive Share-dialog steps, then got shared anyway through a hand-rolled Drive API call with this server's refresh token. `drive.file` is per OAuth client, so only this sign-in can share what it uploaded; the separate `mint-drive-token.py` token cannot. Returning the list lets the caller confirm the audience without a second call |

**Not built yet: a second account.** A personal Google account would be a second config dir (`GSHEETS_CONFIG_DIR`) with its own `auth`, registered as a second server name (e.g. `gsheets-personal`) with that env var set.
