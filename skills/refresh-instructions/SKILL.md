# Refresh Instructions

Three passes on the same file, in order: **restructure** → **condense** → **unhobble**, with a reorganization of the set between condense and unhobble (step 6b). Condense works on correctly-ordered content; unhobble works on tight prose instead of fighting structure and density at once.

This skill sequences the three; all mechanics live in `syafiqkit:haiku` (snapshot, verify, patch discipline).

## Should you run all three passes?

| Condition | Action |
|---|---|
| File is already well-structured AND tight | Run only `unhobble-instructions` |
| File is bloated OR misordered | Run all three |
| File is structured but density unknown | Check bytes per line (`wc -c` ÷ `wc -l`): above roughly 120–150 is dense, so run condense |
| File holds a markdown table the repo's formatter pads (Prettier, oxfmt, `vp fmt`) | Measure the padding before judging density (📖 `references/process-details.md` § Measuring table padding). Padding is not wording, so Pass 1 turns the table into bullets, then density is checked again |
| A `decisions/` file under its ~40 KB that is mostly decision blocks, verbatim quotes or a meeting record | Dense by bytes per line, yet `condense-task-doc` keeps all three whole, so condense moves little (under 2% across 30 such files, 17/11/2026): run Pass 1 and 3 only, and say so in the scope line |
| File is over its size budget | Bloated, however tidy. A budget only triggers a refresh (📖 `../condense-claude-md/SKILL.md` Trigger paragraph): **every condense prompt says "no byte target, cut until the next cut would remove a fact a future session acts on"** and quotes no figure or range. A SKILL.md's budget is the 5,000-token re-attach limit, counted with a tokenizer after the last pass (📖 `../update-plugin/references/harness-constraints.md`); a byte target derived from it passed `done` at 5,026 tokens (2026-10-27). **Before Pass 1, judge whether a split suits the file**: sections serving different readers, or a size condensing alone won't bring under the trigger. If so, split inside this refresh by `condense-claude-md`'s split rule (14/11/2026: a 46 KB companion ran three passes to 41 KB; the split was knowable from the first read) |

**Don't use "the invocation added work", "it ran earlier" or "it is already tight" as reason to skip, and a hand edit never stands in for a pass.** A file over its budget runs all three dispatched passes; "risk higher than gain" is what protected-instance lists are for, not an exit. Check per-file tightness via `wc -l` and `wc -c`, independent of what invoked the skill or prior sessions.

**On files without a template owner (README, runbook, design doc), "well-structured" means rules sit where readers need them, not a template borrowed from another file type.** Where the target resembles a PRD or architecture doc, 📖 `../setup-project-docs/references/standard-shapes.md` is authority. Decide its native shape before writing Pass 1's prompt; if restructure would have nothing to do, say so.

## Pick the skills by file type

| Target | Pass 1 (restructure) | Pass 2 (condense) | Pass 3 (unhobble) |
|---|---|---|---|
| `CLAUDE.md` | `update-claude-docs` (rewrite) | `condense-claude-md` | `unhobble-instructions` |
| Task doc index (`current.md`) | `task-summary` (Full Template) | `condense-task-doc` | `unhobble-instructions` |
| Task doc theme file (`decisions/*.md`) | `task-summary` (theme-file shape per `templates.md#theme-file`) | `condense-task-doc` | `unhobble-instructions` |
| Project doc set (`docs/PRD.md`, `ARCHITECTURE.md`, `ARCHITECTURE-ESSENTIALS.md`) | `setup-project-docs` (update) | `condense-task-doc` | `unhobble-instructions` |
| CLAUDE.md companion (`.claude-companions/**/*.md`) | `update-claude-docs` (rewrite, symptom-router shape) | `condense-claude-md` | `unhobble-instructions` |
| Skill or agent file (`SKILL.md`, its `references/*.md`, a module entry file, `.claude/agents/*.md`) | restructure by own shape (the steps a session walks first; rare branches to `references/` with a pointer) | `condense-claude-md` | `unhobble-instructions` |
| Any other living doc (README, runbook, spec sibling) | restructure by own shape | `condense-task-doc` | `unhobble-instructions` |

**`condense-task-doc` on the bottom two rows is deliberate.** Its keep-test is facts-based, not file-type-based: would losing this cause a future session to act incorrectly? 📖 `../condense-task-doc/` covers spec siblings and docs without templated headings.

## Process

1. **Resolve TARGET SET explicitly, and state it before Pass 1** in one line that names the files and the reason for any exclusion, and says when the set is a guess.
   - **Named set.** Resolve the words ("our claude.md sets") against the working directory, not the repo root.
   - **Bare invocation** (or as vague as "refresh the docs"). The target is first every living doc this session wrote or flagged, instruction files included (a task doc, a skill, reference or agent file edited, a doc `/done` reported over budget), then the working directory's CLAUDE.md. With nothing touched and no CLAUDE.md there, ask rather than climb to a parent (📖 `references/process-details.md` § Target-set incidents).
   - **CLAUDE.md unit.** A CLAUDE.md set ("all claude.md") is each CLAUDE.md and CLAUDE.local.md plus every `.claude-companions/**/*.md` beside it, gitignored `local/` ones included, each a CLAUDE.md in its own right; credential-holding ones go through § A target that holds credentials, never out of the set. Condense a parent after its companions, so it can move content into them.
   - **Task doc unit.** `current.md` plus its `decisions/*.md` siblings, one document across files. **Siblings grow unattended while passing sessions refresh the index, so they hold the density the refresh exists to fix**; `ls -lc current.md decisions/*.md` shows each one's density.
   - **Source captures** stay in the set. Each pass skill guards its own (`condense-task-doc` § source capture keeps every quote; `unhobble-instructions` skips it), so hand it over rather than skip a pass. **Tell: your scope line excludes a sibling as "verbatim", "capture" or "read by scripts".**
   - **Skill unit.** `SKILL.md` plus the files it routes to. Name them up front, and put any left out in the scope line with its reason. A vendored file whose scripts cite it by step or rule number keeps that numbering. A vendored skill is in scope like any other, since upstream's writing is not a reason to leave it over budget. First save upstream's file untouched at `upstream/SKILL.upstream.md`. Then record each move in its `SOURCE.md`, so a later upstream release merges three-way: diff the old upstream file against the new one, then apply the changes to the moved passages (28/11/2026: two vendored skills were first left out as "vendored", and the user answered "should be fine as long we can somehow reconcile").
   - Incidents: 📖 `references/process-details.md` § Target-set incidents.

2. **Snapshot** byte and line count before Pass 1. Probe git once (`git rev-parse --git-dir`, `git rev-parse HEAD`); where either fails, use `wc`/`cmp` and mtime (📖 `../_shared/references/verifying-a-write-landed.md`). **A target holding passwords or keys** gets a masked copy and a token-set survival check, not a printed diff (📖 `references/process-details.md` § A target that holds credentials).

3. **Load `Skill(haiku)` before each pass's prompt** (Pass 1, again before Pass 2, again before Pass 3). A repeat load can answer "already loaded" and attach nothing; then open `../haiku/SKILL.md` at `## Writing the prompt` first. Never list several skills in one prompt; they overwrite each other. Each prompt needs:
   - Banned git verbs named: `commit`, `push`, `stash`, `reset`, `checkout -- .`, `clean`
   - Target file type and shape (e.g., "conform to Full Template" for a task doc index)
   - Protected facts as NAMED INSTANCES with costs. A form-based class ("keep all `⚠️` lines") can't be tested; "the 2026-09-06 chunk-load incident, the only evidence this rule exists" can. A rule the file records as failing from recall ("this rule does not fire from recall", "recurred") goes on the list by name and stays a hard rule: an unhobble pass reads a hard rule beside a softer exception as a contradiction and softens it, so the repair is an exception the file already states, written into the rule's own sentence, never an invented one (📖 `references/process-details.md` § Protecting facts when building the list). A sentence another file quotes goes on the list as "verbatim, with nothing added beside it". **On a file over budget, an incident story is protected by its destination, not its location:** name where the full story may move; condense keeps the rule plus one figure and a pointer. Lock in place only a sentence nothing else records and no rule line restates (14/11/2026: about 20 locked stories held a pass at 41 KB). **List only facts you checked this session**; an unverified one goes in as a claim to check against the code, never as "keep as is" (a false write-guard claim survived three passes that way).
   - A structural boundary for this pass: `condense-task-doc` measures row counts (deliberate deletions); `unhobble-instructions` names whether anything became a principle or left the hot path
   - Where a pass may move text into an existing file, a sentence to read the destination first and, where it already states the rule, delete from the source and point at it instead of appending a copy (22/11/2026: a `uiux` restructure appended 8 paragraphs, 6 restating sections already there).
   - From Pass 2 on, a sentence saying the target's uncommitted diff is the earlier pass's own output: condense skills gate on a peer's uncommitted work, and an unexplained staged rewrite a few minutes old looks exactly like one: measured 04/11/2026, a `condense-claude-md` agent stopped on Pass 1's restructure and wrote nothing.
   - The current-state facts you verified, in every pass's prompt, Pass 1 included: a restructure rewrites status lines too (04/11/2026: a Pass 1 agent called a feature live on production "switched off")
   - For Pass 3 on a task-doc set, or any target whose Pass 2 moved content out: the file as it stood BEFORE Pass 2, and an instruction to restore from it any rejected alternative, quoted wording, measured figure or stated reason whose loss changes what a reader would conclude, unless a 📖 pointer's destination holds it. The agent proves that by grepping a distinctive phrase at the destination and quoting the hit or the zero; relocated text read as lost puts the file back over budget. Condense trims inside decision records though `condense-task-doc` keeps them whole, and no check between passes reads for it (📖 `references/process-details.md` § Incidents behind the restore and sweep rules).

4. **Dispatch Pass 1**, then verify (byte/line diff, then read the whole file for meaning). Where Pass 1 turned rows into decision blocks, check the new `**Rejected**` and `**Problem**` fields against the snapshot (📖 `references/process-details.md` § Pass 1 that turned rows into decision blocks). A pass that split the file also gets 📖 `../_shared/references/verifying-a-relocation.md` before Pass 2, since the split skill's own check never runs when `update-claude-docs` did the split.

5. **Snapshot again**, into a new folder per pass; never write into an earlier pass's snapshot. Pass 3's restore check reads the pre-condense copy, so a file a split created later goes in the later snapshot only.

6. **Dispatch Pass 2**, then verify. A condense that stops early because "the rest is protected" or at a byte figure, while narration, repetition or movable incident stories remain, has found a defect in the prompt, not a floor: loosen the protection or run the split, re-dispatch the same skill, then go on. A hand-written prompt in its place drops that skill's rules. The count gate and the named list check only what you thought to name. Before Pass 3, have a fresh reviewer compare the pre-condense snapshot with the result section by section for rules deleted rather than moved, and, where other files extract from this one (an `ARCHITECTURE-ESSENTIALS.md` "Extracts:" label, a quoted sentence), whether each extract's source sentence survives (18/11/2026: six unnamed rules vanished past every count; 20/11: about 50 facts). Save each unit's verbatim losses to a file its Pass 3 prompt names. **Tell: your Pass 2 verification is a grep of phrases you listed in the prompt.**

6b. **Reorganize where it changes loading** (§ Key Principles): plan moves across the whole set yourself, since one file's agent cannot see where another file's rule belongs; each move passes 📖 `references/process-details.md` § Reorganization checks; dispatch, sweep citations, verify destinations. "Nothing would load differently" is valid.

7. **Snapshot again.**

8. **Dispatch Pass 3**, verify. Then a fresh reviewer compares the pass-0 snapshot with the final files. It looks for any rule that governs an act that can't be undone (commit, push, post, send, delete, create in a live system) and now sits only behind a pointer. Each one goes back inline at its step. The between-pass reviewer misses these, because a moved rule reads as kept. **Tell: the pointer at an irreversible step is all that remains of its rule.** (28/11/2026: after twelve refreshes, the rule keeping customer data out of `ship`'s release captures, and the live-provider hold, survived only in references.)

9. **Report pass-by-pass**, not net diff: readers deciding whether to trust the result need to know what each pass moved. A credential target's snapshots and check file stay until `/done`'s reviewers return, not until this report (📖 `references/process-details.md` § A target that holds credentials).

**Stop between passes if verification fails.** A condense running on an unverified restructure compounds what restructure dropped. Patch or revert, then snapshot again before continuing.

**Encode counts in the prompt as a gate, for every list or table a condense pass may touch, and again after any patch between passes:** `"This file should have 18 gotchas and 8 related paths; if you see fewer, stop and report rather than proceeding."` The agent who can still see a mismatch catches it here. A section protected by name has no count to fail, and bullets folded into a paragraph lose items while the report says nothing moved (06/11/2026: a condense folded 20 laws into five paragraphs, dropped about ten, and reported the section intact). Where content may move out, the count spans this file plus the named destinations, so a relocated item counts as kept.

**With one agent per file in parallel, the cross-file citation sweep is yours, because no agent can do it.** An agent that renumbers a list or renames a heading sweeps only its own file. After every pass, grep the whole set for citation syntax (`step [0-9]`, `rule [0-9]`, `§ <heading>`), not old labels, and check each hit still names what it meant, including any citation an agent reports correcting. An agent may not write into a sibling another agent edits in the same pass: its prompt names those siblings as closed destinations and asks it to list moved text verbatim in its report, for you to place after the pass. The harness runs at most 20 subagents at once and does not retry a rejected dispatch, so a larger set goes out in waves from a queue kept on disk. A set too big to verify from one context goes to one manager agent per unit (📖 `references/process-details.md` § A manager per unit).

**Tell each condense prompt whether provenance on a claim ("checked on Packagist", "proven by a probe file") is process detail or evidence.** Condense strips it as verification narration; unhobble, restoring against the pre-Pass-2 copy, puts it back, so both churn the same lines. Provenance recording how a claim was verified is evidence; keep it unless another line carries the same check.

## Key Principles

**State scope explicitly.** Silent narrowing to one file when the directory holds siblings, or a silent assumption about what a prompt may extract, lets rewording pass for structural work: bytes fall while line count hides that nothing moved. Name the files in scope and where extracted text may land, and give the agent a decision rather than a silence to fill. **Never forbid extraction on a file over budget:** moving incidents out is `condense-claude-md`'s main lever, and a ban leaves it a floor it reports truthfully. Protect anchors and pointers by checking them after the pass, not by banning the move.

**File organization is in scope with no limit, judged by what it does to loading** (the user, 20/11/2026). Split, merge, create a companion or move a rule between levels without asking, whenever the result loads less every session or puts a rule where the moment it applies finds it. Always-loaded files (root `CLAUDE.md`, `CLAUDE.local.md`) keep what every session needs plus 📖 pointers; a rule for one folder goes to that folder's `CLAUDE.md`, which loads only when work touches it; one-moment detail goes to a companion behind a pointer naming the moment. A `.claude/rules/` file with `paths:` loads in full every session, so it is not a lever (📖 `../update-claude-docs/references/structure.md`). A reshuffle that changes nothing about loading is churn. Each move updates the files citing the old place, and a standalone folder keeps its pointers resolvable from its own root.

**Don't ask permission at checkpoints.** Invoking this skill authorises the whole sequence. A verified pass is a reason to continue, not to re-ask (📖 `references/process-details.md` § When to pause between passes — the real case).

**Verify structurally, not by counting survivors.** A "no edits warranted" verdict is legitimate and also the cheapest fail-state: re-take any number its reasoning rests on. A pass claiming changes must say whether anything became principle or left the hot path; otherwise it only reworded. An extraction is verified on both sides: sources shrank, and the companion appeared. After Pass 3, read the body against the frontmatter `description`, which no pass may edit: an unhobble pass reconciling two rules can make the body contradict the description, and no byte, pointer or anchor check sees it.

**On a target that makes claims about a codebase (agent memory, task docs), no pass checks whether a surviving claim is still true.** Words like "unfixed", "still missing", "in-flight" survive every pass. Put the reverse check in the condense prompt: re-check each open-state claim against the code, not only those being cut. A relocated story carries its state words to a destination no pass visits, so read each relocated open-state claim against the code yourself before reporting. The check cuts both ways: an empty grep becomes a dated "not in code" fact, so give every parallel agent the verified current-state facts, and grep each new "absent / does not exist / design-only" correction before the next pass builds on it (📖 `references/process-details.md` § Incidents behind the restore and sweep rules, 2026-10-10).
