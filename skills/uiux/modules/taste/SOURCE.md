## Known gaps

- `library/scenes.json` does not exist at the vendored commit, and no commit in upstream's history has ever held it (checked 15/11/2026, commits API for that path returns none, and it is a 404 on `main` too). The per-scene files `assets/scenes/<id>.js` and `<id>.css`, and the `assets/scenes/demo/<id>.html` pages, are also absent at the vendored commit, which ships only `assets/scenes/stage.js` and `stage.css`. `references/scenes.md` (§ 9), `MODULE.md` § Files and `references/run.md` step 6 describe them anyway, so `scripts/draw.mjs` (which reads `library/scenes.json` only if present) deals no scenes.
- Upstream has scene files only from 2.5.0 (commit `f2d14704448d71f46256dff9e06cb5ae613ead9c`, 03/11/2026) onward, in a different layout: `assets/scenes/<id>/{scene.js,scene.css,meta.json,demo.html}` for 11 scenes, plus `assets/scenes/{index.json,lib.js,print.js,scenes.css,scenes.js}`, and `stage.js` and `stage.css` are gone. That is a different system from the one vendored here, and 2.5.0 also removed this version's app-screen path, direction deal and juror critique, so it was not merged in here. The owner chose (15/11/2026) to keep both: 2.5.1 is vendored whole as the sibling module `../taste-web/`, which supplies the scroll scenes. A scene a page from this module needs is taken from there; this module's own scene catalogue stays empty.

## Requirements

The scripts need Node 22 or newer and an installed Chrome, Edge or Chromium; `scripts/assets.mjs` also needs network access. They install nothing and use no API keys. Run them from the project's root so working files land in `.taste-skill/` there.
