# Condense Task Doc

Fewest tokens for the same or better meaning, never fewer at the cost of meaning (📖 `../_shared/references/writing-style.md`). Maximum signal-to-noise: a cold-start agent should be able to read the doc in under 2 minutes and act correctly. Every line must earn its place — but earning its place is judged after verifying nothing load-bearing left with it, not instead of that check.

**This skill is the single source of truth for task-doc size and cut/keep policy**: thresholds, budgets a doc declares for itself, the split-into-`decisions/<theme>.md` decision, and every cut/keep rule. `claude-md-pruner` (legacy name; it prunes task docs too) delegates sizing verdicts here; its own lane is staleness checked against the live codebase, which this skill does not do. CLAUDE.md files use `condense-claude-md`.

## The Underlying Principle

Everything in this skill comes down to one test: **Is this fact derivable by a competent engineer reading the code, or would losing it cause a future session to act incorrectly?** 

Investigation narratives, evidence, and verification logs fail that test — git history already carries them. A counter-intuitive project-specific behavior, a silent-failure gotcha, or a non-obvious ordering constraint passes it. Hold this test through every decision rather than re-deriving its application per section.

## What Gets Cut vs. What Stays

The distinction is whether the material survives the underlying test. Apply the test to whole rows, sentences, and sections. The long form of each rule below, with its measured incident, is in 📖 `references/section-rules.md` § Worked incidents.

**Derivable facts (delete):** Investigation narratives, evidence of how something was found, verification logs, commit SHAs outside Last Session, duplicated facts living in multiple sections, historical metrics and stale lists, git-tracked state ("committed"/"pushed"), and sections that only exist as dated incident logs. These all have permanent homes in git history. Similarly, drop dated evidence from rows ("confirmed X=Y on prod" → "verified"). **This list is for task docs.** A reference companion another file points readers to *for* its incidents keeps them as content: condense the wording around them, and the no-emoji rule below covers task docs only, never a companion's existing markers. (2026-09-25: a condense pass on companions deleted a flake rate the hot file cites by name.)

**"Derivable from the code" is true of a fact, never of a sibling file.** A stories or acceptance-scenarios file records intent, which code confirms but does not derive, and where the two disagree the disagreement is the most valuable line in the set. Condense a spec sibling row by row. Any deletion justified by "lives in tests/code" names the survivor and checks it is there first. (2026-09-04: a 285-line stories file was replaced by a 16-line note naming test targets that did not exist.)

**Inert explanation (delete):** Root cause narration beyond what a future session needs to *recognize* a recurrence. A reader doesn't need the story of how it failed, just the signature that will let them spot it again.

**Reordering a list strands the citations that point into it.** A numbered list's `Step N` / `rule N` citations, and an unordered log cited by position ("row 8 above"), keep their wording while their target moves. Deleting a cross-reference as "dead" because its number stopped matching is the move that looks like tidying, yet the live breakage is a citation whose number still exists and now means something else. Sweep for the citation pattern, never the old label (`Step [0-9]`, `rule [0-9]+`, `row [0-9]`, `above`, `below`), here and in sibling docs or skills, since the old label is usually gone and grepping it returns zero. Re-check each hit's neighbour by content. (2026-09-15, 2026-09-18: section-rules § Renumbered citations and § Unordered bullet logs.) **Tell: you are deleting a cross-reference whose target number stopped matching, in a pass that changed the numbers.**

**Cutting a claim's evidence while keeping the claim leaves an assertion the doc cannot support.** Strip the figure and a grounded finding becomes an appeal to authority, and the next pass cuts the claim too. Keep the figure, or cut the claim it supports, never the claim alone. **Tell: your diff removes a percentage, a count or a date from a row whose topic sentence still asserts a measurement.**

**No warning emoji in output.** Never write `⚠️` into a task doc. Lead the callout with the bolded claim itself — the same "mechanism + measured incident + Tell:" shape carries the weight; the emoji added nothing a reader couldn't get from the words. Strip any `⚠️` already in the doc as part of a condense pass, without touching the surrounding prose.

**Compressed (not deleted):** Long multi-sentence rows → fix description + one-line summary. Quick Start > 15 lines → drop anything already restated in Bugs Fixed or Critical Gotchas. Last Session > 5 bullets → keep only what hasn't folded into a Decision or Gotcha row.

**Preserved (essential facts):** Counter-intuitive project behaviors (e.g. "successful_syncs:1 = dispatch, NOT API success"), gotchas that look safe but fail silently (e.g. "combo `available_qty` is always 0 in DB, use getComboStock()"), non-obvious ordering constraints, and current-state facts needed to pick up work (e.g. "B14 deployed as cherry-pick, not feature branch SHA"). Do not preserve implementation detail obvious from the code. Decision blocks (`### D-…`) and sourced research are preserved whole: they may move to a sibling file, never be shortened in place. The cut/keep test above applies to narrative, not to the record of why something was chosen. A condense pass trimmed inside decision records anyway (2026-10-10), so do not trim them even when the byte target is close.

**A marked gap and a provenance tag are content, not staleness.** Leave alone a heading whose body is only `[TBD — no target recorded]` and inline `[SOURCED]`/`[INFERRED]`/`[TBD]` tags, both written by `setup-project-docs`. Deleting one erases the only record that the gap exists, and makes it invisible to the person who could close it in a sentence. Same reasoning as *Required sections* below.

**Duplicated facts:** If a gotcha lives in Critical Gotchas AND Quick Start AND LLM-CONTEXT, keep it once and point to it from the others. Merging two open items into one keeps the higher priority marker of the two, because the lower one silently downgrades work someone ranked urgent. Before trusting any pointer, grep the target for the fact — a pointer to missing content is worse than duplication.

**Required sections:** Task Status, Bugs Fixed, Critical Gotchas, and Next Steps may lose every row and still keep their heading — use a pointer row (`| — | see decisions/<theme>.md |`) instead of deleting. A missing heading is invisible to later checks.

## Process

**Prerequisites:** Before starting, check ownership. This skill rewrites whole files in place. Judge by diff *content* (📖 `../_shared/references/diff-ownership.md`); a dirty doc is a baseline, not a measurement problem. A live peer can be known before bytes reach disk (📖 `../_shared/references/cross-session-messaging.md`). The ordinary case: a mature doc was written by sessions long gone, and "another session committed this" describes git history, not a reason to defer. Rewriting committed content is what this skill does.

**Read `../task-summary/references/templates.md`** for canonical section headings, table column names, and field order.

**Core facts first:**
- **Never invent content.** Only restructure what exists. Compress rather than rewrite if a fact is ambiguous.
- **Structural choices belong with the user.** Condensing the text needs no permission, but choosing between competing structures (split vs. condense, keep vs. delete a section) changes what the doc becomes. Surface competing options at the point the choice arises and let the caller decide which path the run takes.
- **Open actionables belong in the doc and don't count as bloat.** A Next Steps item still open stays, even at the cost of lines. An item marked ✅ or in past tense can move or merge. An item superseded by a decision (blocker resolved, platform moved, dependency deleted) is retired in place as `[x]` with the evidence that ended it, so a reader who remembers the blocker can see it is gone. Resolve the value first, as `read-summary` requires before honouring a blocker.
- **Preserve LLM-CONTEXT block.** Update it to match condensed content, keep all fields. The `Last updated` field states date + one-line summary of what changed — not environment status (that lives only in Quick Start).
- **Conserve content, not form.** A table's shape is a means. Collapse columns or a table into prose if it reads better. What must survive: any Cause cell carrying greppable specifics (exception class, exact expression, `See <Class>` pointer). Renaming columns you're keeping breaks positional checks and changes nothing a reader sees.

**Execution flow:**

1. **Read the full doc SET.** The unit is the feature's documentation, not the path you were handed. `ls` the directory: a `decisions/` subdir is in scope and often bigger than the index — a split doc's `decisions/*.md` can be 2–3× the named file. Measure and report the SET's total, not just the index. The exception is a request that names one decisions file: that file is the whole scope, and the index and siblings stay untouched.

2. **Check bytes first to decide approach.** Line count lies (a MADR restructure grows lines while shrinking bytes). Run `git show HEAD:<path> | wc -c` vs `wc -c <path>` — valid only if the doc was CLEAN at session start. Dirty → capture `wc -c` before your first write, or use `git show :<path>` (staged). (📖 `../_shared/references/two-tier-condense.md`).
   - **Bytes flat or lower:** Restructure, not bloat. Report both deltas and stop.
   - **Bytes grew from new ADRs, >300 lines:** Split instead of condense. Index keeps Quick Start, cross-cutting operational tables, and routing. Theme detail moves to `decisions/*.md`. Before splitting, read 📖 `../task-summary/references/decision-splits.md`'s "Splitting a whole-doc MADR further".
   - **Already split, INDEX still oversized:** Work out how long each `## ` section is and start with the longest, one section usually drives the whole overage, and condensing the rest first wastes the pass. However you measure, a `##`-prefixed line inside a fenced block looks like a heading, so a doc full of shell examples will read slightly long. When that section is self-contained and cited from outside the doc (a client question list with its answered tables), move it verbatim to a `decisions/<theme>.md` and leave a one-line-per-item summary table behind. That table keeps whatever a reader uses to find an item from outside (a second numbering another party quotes back, an ID in a sent message), the working assumption each open item carries until answered, the conflict keeping it open, and "pending confirmation" on anything acted on before confirmation. Once a second numbering exists, qualify every bare "question N" as this doc's numbering. Rewording the cells to hit a byte target loses the evidence under each answer. (2026-10-10: a 17-question summary dropped the numbering a sent message had used and read an unconfirmed item as settled.)

     Route each row to its owning theme file (its own "see ADR-N" column usually names it). Rows belonging to no theme (env, fixtures) get a descriptively named sibling, not `bugs.md`/`misc.md`.
   - **A decisions file over ~40 KB, whatever the index's size:** judge it per file. Condense what is superseded or repeated, split the rest by topic into sibling `decisions/*.md` files with `current.md` routing to them, or both. A source capture is split, never cut, unless a script or version diff reads it as one file (then it stays whole with a generated outline, per the source-capture rule under step 8). Moved text goes word for word; count headings and table rows before and after. Then re-aim pointers by grepping every mention of the split file's path (`grep -rn "<file>.md" tasks/ docs/`), not only `§ <moved heading>` pointers, and judge each hit against what moved: inbound links cite moved content as "rows 55 to 60 table", "Q66 in <file>" or "later ones in <file>" just as often, and those still resolve to the router while the fact sits elsewhere (📖 `../task-summary/references/decision-splits.md` § When a single `decisions/<theme>.md` itself outgrows budget). (2026-11-12: a heading-only sweep missed five of eleven.)
   - **Bytes grew from accumulated cruft:** Condense and continue.
   - **Non-task-doc living-doc (CLAUDE.local.md, a runbook, any target with no MADR structure and no `decisions/*.md` sibling), still large after condensing relative to "loads every session":** the MADR branch above doesn't apply, but the file can still split along a companion axis. Apply `condense-claude-md`'s Lever #2 test (📖 `../condense-claude-md/references/split-decision-tree.md`, which generalizes beyond CLAUDE.md). A **routine choice** stays inline. A **symptom-indexed** section (a gotcha table, a debug recipe, infra internals consulted only during an incident) that a companion directory the file already cites could hold is a split candidate. The burden is on not splitting: name why a symptom-indexed section stays resident. (2026-09-16: a condense pass kept a 130-line incident block inline beside a companion directory the file already cited.)

3. **Find what to delete:** Identify `## Investigation` or narrative-only sections (primary bloat sources). Scan for duplication across the whole set with `grep -rl` on 2–3 critical phrases — a per-file pass is blind to cross-file cases. Within a file: phrases in >2 sections, or Bugs Fixed rows whose bug ID also appears in Critical Gotchas. Across files: Bugs Fixed rows explained fully in the index *and* fully in their owning `decisions/*.md` — collapse the index side to a pointer.

4. **Row-existence pass:** For every row in Critical Gotchas and Key Technical Decisions, apply the keep-test ("would losing this cause incorrect action?") and **delete** (not shorten) rows that fail it. A doc with many rows usually loses some here. This is separate from sentence compression and must happen first. A pass that deletes none has probably skipped the test, and step 5's row arithmetic shows it.

   The test is indifferent to age, so a fact written minutes ago is weighed the same as one sitting for months. On rows this session added, deleting one means justifying why the reasoning for adding it no longer holds, rather than merely that it looks derivable — a heavier bar, but not a ban. A row redundant with something else in the same session is a fair cut; what the bar catches is erasing a fact somebody judged worth recording without explaining why.

5. **Execute and measure:** Most condensing is an `Edit` job (section rewrites, row deletions). Count BOTH lines and bytes before and after (`wc -lc`) for every file in the SET. Report per-file deltas plus the set total. Also report row count: gotcha/decision rows before, after, and how many were deliberately deleted. A pass skipping step 4 produces the same tidy byte delta as one that ran it, so row arithmetic is the signal; a set of deletions that doesn't reconcile against the byte delta indicates the row-existence pass got skipped. (📖 `../_shared/references/two-tier-condense.md` for write-mode choice and diff-baseline rules.)

6. **After all writes land, run the duplication check again** (`grep -rl` from step 3). Section-by-section editing can reintroduce the same fact across files. The per-file diff is blind by construction to that case; only a set-wide grep catches it. Confirm each file's last line is real content (`tail -c 40 <file>`): a full-file write can carry in the `<content>` wrapper that a `Read` result arrives in, as a literal trailing line.

7. **Account for where the bytes went, before reporting.** A pass that deleted content must name where it went or justify what was cut. A restructure moves text between files (index shrinks, `decisions/*.md` siblings grow or stay flat), so the set total should be roughly flat; a drop means bytes left without a destination. A pure condense (rows genuinely deleted by the keep-test) should name the facts judged non-essential and why. A split moves decision blocks to siblings (the set total holds flat or rises). A dedup collapse removes one copy of a duplicated fact, leaving the survivor unchanged — here the separation from real deletion is confirming the survivor still carries the fact.

   Where bytes leave a file without a destination and without justification for each cut, state that clearly rather than reporting tidy deltas and letting the caller notice the issue. The caller sees only what you report.

8. **Target: ≤300 lines for the index (`current.md`)**, measured without the Next Steps section: open actionables stay in the index and don't count against the budget. The budget is the index's alone. A set of several files will normally total well over 300, and that's not an overage. Each `decisions/*.md` file is judged on its own: does it hold one topic, is it dense, does it repeat another file? A doc over this mark by live backlog alone has passed; report it with the backlog size rather than cutting actionables to stay under the number. Being under budget doesn't mean skipping step 4. If a section is hard to read on a cold start (stacked parentheticals, paragraphs a reader has to reread), tighten it even under budget, since a tidy count disguises readability debt. Long lines (past about 120–150 bytes on average), paragraphs past about 500 characters and sections past about 4 KB are where this usually shows, not the test itself. Tightening never reaches a decision block (see Preserved).

   **A source capture is exempt from condensing for size, not from splitting.** That's a `decisions/` file holding the only copy of external material whose original is gone (client PDFs, chat messages, meeting notes). Dedupe it, but keep every figure, name and quoted line. A verbatim copy (terms, a policy, a contract) is not edited at all. Past ~40 KB, split it along the source's own sections and route `current.md` to the parts, unless the check below finds something that reads it as one file. (2026-10-02: a condense pass cut a 265-line client capture by 43 lines and was reverted whole.)

   ⚠️ **Before splitting any capture, grep the repo for its file name in scripts, builds and CI** (`grep -rln "<file>.md" --exclude-dir=node_modules --exclude-dir=vendor --exclude-dir=.git . | grep -v '\.md$'`), and read the owning doc for "one file" or "one commit per version". If anything reads it at that path, or its version history is read through `git diff` on it, a split breaks them while every heading count still matches. Keep it whole and give readers a map instead. If the owning doc already names a generator for this file's outline, run that one and stop. Otherwise `python3 -I ${CLAUDE_SKILL_DIR}/scripts/doc_outline.py <file>` writes `<file>-outline.md` beside it, one row per section with its line range and size, and `--check` exits 1 once the outline no longer matches. It reads `#` and underlined headings and whole-line bold sections. Commit the outline with each new version, copy the script into the repo (for example `scripts/doc_outline.py`) and wire `--check` through that copy into whatever gate already runs on that file, since the plugin's own path is a versioned cache folder that gets pruned and that teammates may not have, and point `current.md` at the outline, quoting the exact command with the repo path. The gate's `--check` carries the same `--group`/`--label` flags as generation, since it rebuilds the outline from the flags it is given and reports a correct outline STALE without them. The outline is generated: a later condense, merge or refresh pass regenerates it and never edits it. A copy converted from Word often has its sections as bold lines rather than `#` headings: pass `--group` for each prefix that starts a top-level part and `--label` for a sub-label prefix that is not a section, for example `--group "Stage 1:" --group "Stage 2:" --group "Appendix 1" --label "Included" --label "Screens"`. (14/11/2026: a 160 KB quotation copy read at a fixed path by two scripts was nearly split by an automatic size prompt.) **Tell: you are about to split a verbatim copy and have not grepped for what reads it.**
   - **Still >300 lines after condensing, excess is MADR blocks:** Split Key Technical Decisions into `decisions/<theme>.md` (📖 `../task-summary/references/templates.md#theme-file` for each theme file's shape). A split MOVES a `### D-` block and never rewrites one: carry its text byte-for-byte (a script keyed on the `### D-<slug>` heading through the next `###`/`##` heading is the safe instrument). A sourced research section moves the same way. Paraphrase invents detail (2026-09-08: half-length blocks gained a field the code never had). Prove the move: every `### D-` heading greps once in the set, and distinctive phrases from the rewrite grep in the source. Then run 📖 `../_shared/references/verifying-a-relocation.md`, since a split breaks routes into the moved content. Report both the condensed delta and the split.
