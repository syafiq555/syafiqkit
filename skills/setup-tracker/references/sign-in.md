# Sign-in for the build

How the build script signs in, which account the sheet lands in, and the fallbacks. Read this before a first build, when no sign-in exists, or when the sheet belongs in an account other than the sign-in's.

**The script signs in with the plugin's `gsheets-mcp` sign-in** (`~/.config/syafiqkit/google`, or `GSHEETS_CONFIG_DIR`): it turns the stored refresh token into an access token itself, so no token passes through the transcript. The sheet lands in that sign-in's account, and nothing on disk names it (`check` says only "signed in", and the token files hold no email), so confirm the account with the user, or open a sheet the sign-in already made and read its signed-in account, before building. Check that a sign-in exists (`gsheets-mcp check` in the plugin's `tools/gsheets-mcp/bin/`, or the files `client.json` and `refresh.json`). Without one, a first sign-in needs `bun` and the user's own Google OAuth client of the Desktop-app type: `gsheets-mcp auth --client <path to client.json>`, once (`tools/gsheets-mcp/README.md`). A user with no Google Cloud project gets the whole setup from the `setup-tools` skill. The script reads the files directly, so the connection need not be switched on in this repo. When the sheet belongs in another account, signing in again may not work: an OAuth client created inside a Google Workspace as Internal refuses every outside account with `Error 403: org_internal`. For a one-off build, use `SHEETS_TOKEN` instead, taken from the Playground described below while signed in as that account. For an account you will use again, give it a sign-in folder of its own (`tools/gsheets-mcp/README.md`) and build with `GSHEETS_CONFIG_DIR` pointing at it. Afterwards have the user remove "Google OAuth 2.0 Playground" from that account's third-party access, because the refresh token it issued stays valid for days. `SHEETS_TOKEN` is an OAuth access token with the `https://www.googleapis.com/auth/spreadsheets` scope; it lasts about an hour and wins when set. Get one from the OAuth 2.0 Playground (pick the Sheets API v4 scope, sign in, exchange the code, copy the access token). Skip `gcloud auth application-default login`: Google answers it with "This app is blocked" for the Sheets scope unless you pass your own `--client-id-file`. With no sign-in at all, hand over the finished config and build the sheet by hand from it.

The owner shares the file from that account's My Drive (sharing limits in `references/sheets-api-gotchas.md`).
