# Moving uploads to Cloudflare R2

R2 is free up to 10 GB stored, 1 million writes and 10 million reads a month, with no download fees (Cloudflare's R2 pricing page, read 25/11/2026). The first bucket asks for a card but bills $0 within that.

**A custom domain makes everything in the bucket public.** That suits photos a shop shows anyway. Private files (IDs, invoices, signed documents) go in a bucket with no custom domain and are served through the app with signed URLs (`Storage::temporaryUrl`), or stay on the server.

**Order, because a push to the deploy branch deploys:** ship the code first (the R2 disk config and the S3 package, for Laravel `league/flysystem-aws-s3-v3`, with the upload disk read from an env value), then the keys, the test write, the copy of existing files, and only then the switch of the env value.

## What the owner clicks

Give these one step at a time; the owner sends screenshots, and each one is checked before the next step.

1. **Storage & databases → R2 Object Storage → Create bucket.** Name `<project>` (permanent), Location Automatic, storage class Standard.
2. **The bucket → Settings → Custom Domains → Add**: `<name>-photos.<umbrella>`. Cloudflare adds the DNS record itself (proxied, which is right here) and notes that it overrides the `*` record for this one name. Status goes Initializing → Active within minutes. R2 accepts only a domain that is a zone in the bucket's own account. Leave **Public Development URL** off: Cloudflare calls `r2.dev` rate-limited and for development only.
3. **R2 overview → Account Details → Manage API Tokens → Create Account API token**: name `<project>-app`, permission **Object Read & Write**, **Apply to specific buckets only** → the bucket, TTL Forever. The secret shows once.
4. The owner replies "done" without pasting anything.

The bucket's Settings page shows the S3 API address: the endpoint is that address without the trailing `/<bucket>`. The account ID in it is not secret.

## Collecting the keys

Never ask for keys in the chat. Collect them on the owner's Mac in hidden dialogs, write them to a private file, copy it up, and delete it locally:

```bash
umask 077; f=/tmp/<project>-r2.env
K=$(osascript -e 'text returned of (display dialog "Paste the R2 Access Key ID" default answer "" with hidden answer)') || exit 1
S=$(osascript -e 'text returned of (display dialog "Paste the R2 Secret Access Key" default answer "" with hidden answer)') || exit 1
K=$(printf %s "$K" | tr -d '[:space:]'); S=$(printf %s "$S" | tr -d '[:space:]')
printf 'R2_ACCESS_KEY_ID=%s\nR2_SECRET_ACCESS_KEY=%s\nR2_BUCKET=<bucket>\nR2_ENDPOINT=https://<account-id>.r2.cloudflarestorage.com\nR2_PUBLIC_URL=https://<name>-photos.<umbrella>\n' "$K" "$S" > $f
echo "key id ${#K}, secret ${#S}"
remote --scp <server> $f --to /opt/apps/<app>/.r2.tmp && rm -f $f
```

The printed lengths are the only check shown (an R2 key ID is 32 characters, the secret 64). On the server, with a backup of `.env.production` taken: drop any old `R2_*` lines, append `.r2.tmp`, keep mode 600, delete `.r2.tmp`, and print the `R2_*` lines with the two key values masked.

## The app's disk (Laravel)

An S3 disk pointed at R2 needs `region` `auto`, `endpoint` and `url` from the env, `use_path_style_endpoint` true, no `visibility` (R2's S3 compatibility table marks `x-amz-acl` unsupported), and both `request_checksum_calculation` and `response_checksum_validation` set to `when_required`: AWS SDK for PHP 3.337.0 (15/01/2025) made a CRC32 checksum the default on every supporting operation, and simply-rozie's uploads to R2 failed until both were relaxed. Cloudflare's own PHP example does not mention this. Make the app's upload disk an env value (`MEDIA_DISK`) so switching is a settings change, and check every place that writes uploads reads it: Filament's file field falls back to `FILESYSTEM_DISK` unless the media collection names its disk.

Prove it before switching: recreate the container with the keys in, write a test file through the app's own disk (`Storage::disk('r2')->put(...)` in tinker), `curl` its public URL from this Mac, then delete it.

## Moving existing files

Any stack: copy the upload folder from the server's volume to the bucket at the same relative paths (`rclone copy <volume-path> r2:<bucket>` with an rclone R2 remote, or the app's own storage layer), compare file counts and sizes, then point the app's records or config at the new disk.

Laravel with spatie medialibrary: a medialibrary row keeps the disk it was saved to, so changing `MEDIA_DISK` moves only new uploads. For each row on the old disk, copy its `<media id>/` folder (originals, `conversions/`, `responsive-images/`) to R2 at the same paths, compare sizes, then set `disk` and `conversions_disk` to the R2 disk. Count the rows per disk afterwards and `curl` a few of the shop's own image URLs. Keep the server copies until R2 has served for a while, and note them as a cleanup item.

Running a multi-line PHP script on the server: `remote --scp` it, `docker cp` it into the container, then `php artisan tinker --execute "$(cat /tmp/x.php)"` as the app user. `tinker /tmp/x.php` echoes the code and runs nothing.

Then set `MEDIA_DISK` to the R2 disk, recreate, rebuild caches, and confirm the app's config reads it back.
